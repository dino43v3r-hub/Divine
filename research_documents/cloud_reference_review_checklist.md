# Cloud Reference Review Checklist

Type: evidence-quality workflow
Source status: review policy

Daily cloud references are candidate leads, not strong evidence. Review each
candidate before it increases confidence in the pattern.

## Required Checks

1. Original source: confirm the title, author, publication venue, date, and URL.
2. Author expertise: identify whether the author is a theologian, historian,
   scientist, philosopher, practitioner, journalist, or unknown.
3. Source type: classify as primary source, peer-reviewed scholarship, book,
   public theology, pastoral source, news, search result, or speculative source.
4. Claim scope: write the smallest claim the source actually supports.
5. Counterargument: name at least one rival reading or limitation.
6. Tradition and context: note religious tradition, language, era, genre, and
   community context.
7. Copyright safety: store metadata, summaries, and short notes rather than
   copied copyrighted text.
8. Confidence effect: mark whether the source can increase confidence, only
   generate questions, or should be rejected.

## Review Labels

- reviewed_strong_evidence: original source checked, author/context credible,
  claim modest, counterargument included.
- reviewed_limited_evidence: useful but narrow, contested, or missing some
  context.
- candidate_lead_only: interesting but not checked enough.
- reject_or_do_not_use: unreliable, misattributed, irrelevant, or overclaimed.

Rule:

The analyzer may use unreviewed cloud references to ask better questions. It
should not use them as strong support until this checklist is complete.
